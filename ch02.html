2.1Card 数据流模型

Stuart Card 1999：可视化是从「值」到「视图」再到「人脑」的变换链。

理解这条链的最大好处是调试有方向。当图不对时，你能判断问题出在哪一步： 是数据读错了，还是映射错了，还是渲染错了。

演示 · 数据流模型（可点击） 点任一方框看该阶段的职责与常见错误
Card, Mackinlay & Shneiderman (1999), Readings in Information Visualization, "Data State Model".

为什么用这条模型思考问题

新手最常犯的错误是把所有问题都当成「渲染问题」——颜色不对就调颜色。 但多数时候问题出在更上游：聚合粒度不对（数据表错了）、 视觉通道选错了（可视化抽象错了）。先定位阶段，再动手。

⭐关键点：每一步都是「有损压缩」

从值到视图，每一步都在丢弃信息换取可读性。聚合丢弃个体、映射丢弃未编码的字段、渲染丢弃被遮挡的细节。可视化设计的本质，是决定「丢掉什么」。判断标准是：丢掉的是否正好是读者不需要的？

2.2数据分类树：d3.rollup 多层聚合

关键代码 · 三层 rollup

          
// 按「班级 → 性别 → 年龄」三层聚合，叶子是人数
const tree = d3.rollup(
  students,
  v => v.length,                       // 聚合函数：数人数
  d => d.class,                        // 第 1 层键
  d => d.gender,                       // 第 2 层键
  d => d.age                           // 第 3 层键
);

// 展开成 d3.hierarchy 能识别的 {name, children} 结构
function mapToNode(map, name) {
  return {
    name,
    children: [...map.entries()].map(([k, v]) =>
      v instanceof Map ? mapToNode(v, String(k)) : { name: String(k), value: v })
  };
}

        


        

          
💡group 与 rollup 的分工

          
d3.group 只分堆不聚合（叶子仍是记录数组），适合下一步要保留原始记录的场景；d3.rollup 直接给出聚合值。做树图、旭日图通常用 rollup + d3.hierarchy。

        


        

      


      
      

        
2.3树布局：Reingold-Tilford 算法

        
经典规则：兄弟节点尽量靠拢，父节点居中于子节点。


        

          Reingold & Tilford (1981) 给出了"画好一棵树"的四条美学规则：
          ① 同层节点在同一水平线；② 兄弟节点从左到右排布且尽量紧凑；
          ③ 父节点水平居中于其所有子节点；④ 子树无论出现在哪里，形状都相同。
          d3.tree() 实现了这套规则。
        


        

          

            演示 · 新生数据分类树
            悬停节点看路径与人数 · 可切换布局方向
            
            
          

          

          

        


        

          
关键代码 · 三步画树

          
const root = d3.hierarchy(mapToNode(tree, "全部新生"))
  .sum(d => d.value)          // 让每个节点带上「子树总人数」
  .sort((a, b) => b.value - a.value);

d3.tree().size([width, height])(root);   // 布局：算出每个节点的 x, y

// 画连线（links）与节点（nodes）
svg.selectAll(".link").data(root.links()).join("path")
  .attr("d", d3.linkVertical().x(d => d.x).y(d => d.y));

svg.selectAll(".node").data(root.descendants()).join("circle")
  .attr("cx", d => d.x).attr("cy", d => d.y).attr("r", 5);

        


        

          
⭐关键点：布局与渲染分离

          
d3.tree() 只做一件事——算出每个节点的坐标；它不画任何东西。把「布局」和「渲染」分开，意味着同一棵树可以用节点链接、旭日图、缩进列表等不同方式呈现。这正是本章的精髓。

        


        

      


      
      

        
2.4树形列表渲染：classed + 事件委托

        
同一棵树，换成缩进列表；只用一个监听器处理全部点击。


        

          树不一定要画成图。缩进列表（outline）也是一种树可视化，而且更适合精确读取数值。
          这里的关键技术是事件委托：不在每个节点上绑监听器，
          而是只在根容器绑一个，通过 event.target 判断点了谁。

关键代码 · 一个监听器管全部

          
container.addEventListener("click", e => {
  const toggle = e.target.closest(".toggle");   // 点了箭头？
  const row = e.target.closest(".row");         // 还是点了行？
  if (toggle) { toggleNode(toggle.dataset.path); return; }
  if (row) { selectNode(row.dataset.path); }
});

// classed()：把「状态」变成 class，样式交给 CSS
li.classed("open", d => d.open)
  .classed("leaf", d => !d.children);

        


        

          
⚠坑：重复绑定监听器

          
如果每次渲染都 addEventListener，树展开几次就会触发重复回调。事件委托把监听器固定在不会重建的容器上，内部节点随意增删都不会出问题。

        


        

          
💡节点链接图 vs 缩进列表

          
看结构形状（哪层宽、哪里不平衡）用节点链接图；看精确数值与导航用缩进列表。两者底层是同一棵 hierarchy——这就是「布局与渲染分离」的价值。
