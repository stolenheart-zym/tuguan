1.1数据从哪来：加载与字段映射

CSV 是字符串；JS 需要对象。中间这一步叫「行转换」。

CSV 文件里所有东西都是文本。"18" 是字符串不是数字， "2007-08-15" 是字符串不是日期。如果直接拿去算， "18" + "2" 会得到 "182"。所以加载时必须做类型转换。

三个必须记住的坑

        

          
⚠坑一：中文 key

          
CSV 用中文列名给人看没问题，但 JS 对象里不要直接用中文 key。老浏览器对中文标识符容错差，JSON / URL 编码也可能乱码，IDE 的补全与重构支持也不一致。做法是建立一张映射表。

        

        

          
⚠坑二：忘了 trim()

          
"软件工程1班 " 末尾那个空格，会让后续的分组、过滤全部失效——而且极难发现。所有字符串字段都应该 .trim()。

        

        

          
⚠坑三：new Date() 的兼容差异

          
new Date("2007-08-15") 能解析 ISO 格式，但对 "2007/8/15" 表现不一致。稳妥写法是 d3.timeParse("%Y-%m-%d")，解析失败会返回 null，便于显式排查。

        


        

          
关键代码 · 一行完成加载 + 转换

          
const COLUMN_MAP = { "序号":"id", "姓名":"name", "性别":"gender",
                    "生日":"birthday", "年龄":"age", "班级":"class",
                    "籍贯":"hometown", "民族":"ethnic" };

const parseDate = d3.timeParse("%Y-%m-%d");

function transformRow(d) {
  return {
    id:       +d["序号"],              // 一元 + 把字符串转数字
    name:     d["姓名"].trim(),          // trim() 去掉首尾空白
    birthday: parseDate(d["生日"]),      // 用 d3 解析，失败返回 null
    age:      +d["年龄"],
    class:    d["班级"].trim(),
    hometown: d["籍贯"].trim(),
    ethnic:   d["民族"].trim()
  };
}

// d3.csv 的第二个参数直接传「行转换函数」，加载即转换
const data = await d3.csv("data/newstudent.csv", transformRow);

        


        

          
⭐关键点：为什么是 d3.csv(path, row)

          
把转换函数交给 d3.csv，加载和清洗就合成为一步，中间不会残留一份「脏数据」。相反，如果先 await d3.csv(path) 再 .map()，那么在中途出错时，你会同时持有两份不同状态的数据，调试成本翻倍。

        


        

          
💡顺手做一次质量检查

          
加载完成后立刻验证：data.length 是否符合预期、有无 null 日期、数值字段有无 NaN。这一步花十秒钟，能省下后面两小时。

        


        

      


      
      

        
1.2数据的定义：DIKW 金字塔

        
Data → Information → Knowledge → Wisdom，每上一层都多了一种东西。


        

          这是 Russell Ackoff 在 1989 年提出的层级。区分它们的关键不在于「量」，
          而在于加了什么：加上下文成为信息，加关系成为知识，加判断成为智慧。
        


        

          

            演示 · DIKW 金字塔
            点任一层，看它在新生数据里对应什么
          

          

            

            

          

          

            Ackoff, R. (1989), "From Data to Wisdom", Journal of Applied Systems Analysis.
          

        


        
对可视化的意义

        

          可视化的工作边界，主要在 Information → Knowledge 这一段：
          图把信息排布成能看出关系的形式，让人产出知识。
          因此一张好图的标准不是「好看」，而是「是否让人更快地产出正确的知识」。
        


        

          
⭐关键点：可视化不能越级

          
数据是原材料，直接把 80 行表格丢给读者，读者要自己完成全部三层跃迁；而好图替读者完成了「信息 → 知识」这一步。判断一张图好不好，就问：它替读者省掉了哪一层？

        


        

          
📌顺带记住：数据质量四维度

          
Wang & Strong (1996) 提出数据质量的四个维度：准确性、完整性、一致性、时效性。使用任何数据前都应过一遍这四项——尤其是 AI 合成数据。

        


        

      


      
      

        
1.3数据属性：Stevens 四种测量尺度

        
这是整门课最实用的一个判断：先定尺度，再选图。


        

          Stanley Stevens 在 1946 年提出四种测量尺度。它们的区别在于允许的运算逐级增多：
          定类只能判等，定序能判大小，定距能算差值，定比能算倍数。
          用了不该用的运算，结论就是错的——比如「20℃ 是 10℃ 的两倍热」这句话没有意义。

⭐关键点：尺度决定图形，而不是你决定图形

          
    
            
  • 定类 → 只能用位置与色相区分，条形图按频数排序。
    • 
            
  • 定序 → 顺序色阶（sequential），条形必须按等级排列，不能打乱。
    • 
            
  • 定距 → 折线、直方图；有中点时用发散色阶（diverging）。
    • 
            
  • 定比 → 全部可用，且可以使用对数轴（因为有绝对零点）。
    • 
          

        


        

          
⚠最常见的错误：给「定类」用「顺序色阶」

          
用同一蓝色的深浅表示「山东 / 江苏 / 四川」，读者会本能地认为三者有先后。类别之间没有顺序，就必须用色相区分，不能用深浅。

        


        

      


      
      

        
1.4数据变换：把原始表变成可画的形状

        
d3-array 的八个函数，覆盖 90% 的整形需求。


        

          原始数据很少能直接画。你需要筛选、派生、排序、分组、分箱。
          d3-array 把这些操作做成纯函数，可以串联成一条流水线——
          每一步的输出都是下一步的输入，任何一步都能单独检查。
        


        

          

            演示 · 变换流水线
            勾选要执行的步骤，实时看中间结果
          

          

            

            

            

          

          

            
          

        


        

          
d3-array 常用变换

          
// 筛选
data.filter(d => d.age >= 18)

// 派生新字段（map 会返回新数组，不改动原数组）
data.map(d => ({ ...d, birthYear: d.birthday.getFullYear() }))

// 排序（注意：sort 会原地修改，应先 [...data] 复制）
[...data].sort((a, b) => d3.ascending(a.age, b.age))

// 分组统计：rollup 返回 Map
d3.rollup(data, v => v.length, d => d.class)      // 单层：班级 → 人数
d3.rollup(data, v => v.length, d => d.class, d => d.gender) // 多层嵌套

// 求极值 / 分箱 / 累积
d3.extent(data, d => d.age)                       // [min, max]
d3.bin().value(d => d.age).thresholds(6)(data)    // 直方图分箱
d3.group(data, d => d.hometown)                   // 分组但不聚合

        


        

          
⚠坑：sort() 会原地修改数组

          
Array.prototype.sort 直接改动原数组。如果你在多个视图里共用同一份数据，一处排序会静默地改变另一处的顺序。始终写成 [...data].sort(...)。

        


        

          
💡rollup 还是 group？

          
需要聚合出数值（人数、均值、求和）用 d3.rollup，返回 Map(key → 聚合值)；
          只需要把记录分堆用 d3.group，返回 Map(key → 记录数组)。

        


        

      


      
      

        
1.5D3 数据选择器：Data-Join 的三种状态

        
enter / update / exit —— 理解了它，就理解了 D3。


        

          D3 最核心的思想是 Data-Join：把数据数组和 DOM 元素数组做一次对齐。
          对齐结果必然是三种状态之一：
        

        
    
          
  • update — 数据有、元素也有（需要更新属性）
    • 
          
  • enter — 数据有、元素没有（需要新建元素）
    • 
          
  • exit — 元素有、数据没了（需要删除元素）
    • 
        


        

          

            演示 · 三态可视化
            切换数据集，看哪些柱子进入、更新、退出
            
            
          

          

            

              ■ enter 新增
              ■ update 更新
              ■ exit 移除
              
              
            

            

          

          

            
          

        


        

          
关键代码 · 三态的标准写法

          
// key 函数：告诉 D3 "这条数据对应哪个元素"
const bars = svg.selectAll("rect").data(data, d => d.key);

bars.exit()
    .transition().duration(600)
    .attr("height", 0).attr("y", y0)
    .remove();                                   // ① 先退场

bars.enter().append("rect")                      // ② 再进场
    .attr("x", d => x(d.key))
    .attr("y", y0).attr("height", 0)
    .attr("fill", "#1e3a6b")
  .merge(bars)                                   // ③ 合并后统一更新
    .transition().duration(600)
    .attr("x", d => x(d.key))
    .attr("y", d => y(d.value))
    .attr("height", d => y0 - y(d.value));

        


        

          
⭐关键点：必须提供 key 函数

          
不传 key 函数时，D3 默认按下标匹配。数据集一变顺序，所有元素都会被当成「update」而不是 enter/exit，动画就会错乱——同一种颜色会莫名其妙地跳到另一个柱子上。提供了 key 函数（如 d => d.key），D3 才能正确识别「谁是新来的、谁走了」。

        


        

          
⚠坑：过渡动画与数据更新不同步

          
transition() 是异步的。如果在动画未完成时再次更新数据，会产生交错的中间状态。解决办法是给过渡命名（.transition("bar")），或在更新前调用 selection.interrupt()。
